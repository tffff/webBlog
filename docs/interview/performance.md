## 前端性能优化有哪些？
一、加载优化

  - 路由懒加载：拆分路由组件，按需引入，减少首屏js体积
  - 组件懒加载：非可视区域组件延迟加载
  - 资源优化：图片压缩、懒加载、使用cdn加速静态资源、预加载/预解析资源

二、打包构建优化
  - webpack/vite开启代码分割,拆分公共代码、业务代码
  - 开启gzip压缩，减小传输体积
  - 剔除无用依赖，按需引入UI组件库
  - 去除console、打包剔除源码映射文件(sourceMap文件)

三、渲染与代码优化
  - 列表渲染必须加唯一key,避免diff低效
  - 长列表使用虚拟滚动列表，避免大量DOM渲染导致卡顿
  - 合理使用v-if/v-show,避免页面重排和重绘，导致性能问题
  - 防抖节流优化高频触发事件
  - 销毁组件时及时清楚定时器

四、响应式&数据优化
  - 避免全局冗余响应式数据，大对象合理拆分
  - 合理使用`shallowRef`/`shallowReactive`/`shallowDeepReactive`,避免响应式数据过深，导致性能问题
  - 缓存接口请求，避免重复请求

五、其他
  - 开启骨架屏、loading提升用户状态
  - 首屏加载优化、减少首屏请求数量

👉 面试口语：

- 第一是网络层：我们把静态资源全部放到 `CDN`，开启了强缓存和协商缓存，同时开启 `HTTP2`，减少请求延迟。

- 第二是资源加载：通过路由懒加载和 `Webpack` 代码分割减少首屏 JS 体积，配合 `Tree Shaking` 去掉无用代码，并对图片做了压缩和 WebP 处理。

- 第三是渲染优化：首屏使用骨架屏减少白屏感知，长列表使用虚拟列表，避免大量 DOM 渲染导致卡顿。

- 第四是运行时：对滚动、输入等高频事件做了防抖和节流，尽量避免频繁 DOM 操作，减少重排和重绘。

- 第五是体验和监控：我们会用 `Lighthouse` 和 `Web Vitals` 跑性能指标，关注 `FCP`、`LCP` 和 `TTI`，并在上线后持续监控和优化。
